# Munim: 60-second cartoon animation prompt pack

This is the current video direction. It replaces the live-action treatment in `CINEMATIC_DEMO_PROMPTS.md` following the user's request for a cartoonish animated video.

## The reworked concept

**Working title:** Three papers. One clearer claim.

**Runtime:** Exactly 60 seconds, nine scenes. Deliver in 16:9, preferably 1920 x 1080 or higher, on a 24 fps timeline.

**Treatment:** A polished 2D cartoon explainer, with a recurring supplier character and animated paper objects. The workshop and supplier establish the human problem. Simple, accurate product panels explain Munim. The red-pen correction provides the visual payoff. The closing scene shows a supplier holding an organised evidence file, ready to follow up.

**Animation grammar:** Bold readable silhouettes, consistent dark outlines, flat fills, minimal cel shading, purposeful poses, gentle anticipation and settling. Paper transitions join scenes. Smooth digital pans and zooms replace live-action lens directions. One focal action at a time. Character movement is expressive; product values and status labels stay stable and readable.

All scenes can remain animated. For product panels, build an accurate, simplified motion graphic from the actual app layout, source crops and recorded correction sequence. Add exact labels, numbers and Hindi text as editable layers in the video editor. Any simplified interface should carry the small label “Illustrated workflow”. If actual replay footage is inserted, retain “Recorded responses”.

The project palette applies to the visual identity: cool light-grey background, white invoice, faded pink challan, pale yellow purchase order, blue actions and corrections, red failed checks, green Passed marks. The cartoon world can use rounded character shapes; the app panels retain the product's small-radius rectangular controls.

## Generation and assembly workflow

1. Lock one character/prop sheet and one workshop layout. Reuse references in every scene.
2. Generate each scene independently with the shared style prompt and its scene-specific prompt. Request the final timeline length if supported. If the generator offers fixed clip lengths, generate sufficient handles and trim them during editing; ensure its main action remains complete.
3. Generate clean text-free animation plates. Build captions, model/code labels, statuses and exact correction values as editable layers. Generate no full-minute clip containing every event at once.
4. For scenes 3–7, animate a simplified view derived from the actual app. Use the same synthetic case across the document, correction and clock views. Keep “Illustrated workflow” visible. Label the reconstructed replay correction “Recorded example”. If using actual replay capture instead, preserve its provider badge.
5. Use straight cuts and short paper-matching transitions. Character movement may have gentle easing; actual product text should settle quickly and remain still long enough to read.
6. Assemble the exact windows: 6 + 6 + 6 + 7 + 9 + 7 + 8 + 7 + 4 = 60 seconds. Record narration to those windows and add captions clear of source crops, findings and figures.
7. Review at normal speed on a laptop. Viewers should understand the model/code distinction, visible original, user confirmation, calculation working and draft status without pausing. End on an organised file and a prepared supplier.
