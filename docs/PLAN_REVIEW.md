# Plan review (Step 0.7)

Four reviewers cross-checked the planning documents on 2026-10-12. Facts were checked on the web the same evening (secondary sources only; rbi.org.in is blocked from the build machine). Each decision below is binding for the build. The named documents are corrected so they agree.

| # | Problem found | Decision |
| --- | --- | --- |
| D1 | The demo's `0` read as `O` fails GSTIN-FORMAT, not the checksum. The look-alike step then fixes it before any re-read, so the "Gemma re-reads, row turns Passed" moment cannot happen. TESTING's vector also names the wrong position (it is 8, not 9). | The demo misread is the **check character**, using a confusion outside the look-alike map. The generator asserts that GSTIN-CHECKSUM fires and that no look-alike candidate passes, so the model re-read runs and the row can honestly end Passed. A look-alike fix stays `needs_review` (blocking, "Check by hand") and has its own test. A candidate must pass full `gstin.validate`. |
| D2 | The Bank Rate table has one row, effective 2026-10-01, so no rate covers the demo's months. Research says the 5.75% Bank Rate dates from 7 Oct 2026; 5.50% applied from 5 Dec 2025 and 5.75% from 6 Jun 2025 (Bank Rate = MSF). | Seed three rows, all `confirmed: false`, each citing its source: 2025-06-06 5.75, 2025-12-05 5.50, 2026-10-07 5.75. A period with no row raises a typed error ("Add a Bank Rate effective on or before <date>"). The goldens stay as algorithm vectors with explicit rates. On the seeded table the demo shows ₹40,976.71 interest and ₹5,40,976.71 owed. |
| D3 | Only the invoice date is checked for day/month ambiguity, but the challan date sets the money figure. | The rule becomes `DATE-AMBIGUOUS` and covers every date field. It is blocking for challan dates (they feed the clock) and a warning elsewhere. The UI offers the two readings as buttons. Fixtures print the PO date as `02 Mar 2026`. |
| D4 | The day-count convention is not written down; one TESTING case contradicts the goldens. | `d = (as_on - period_start).days`; the as-on day itself is not counted; `days_late = (as_on - due).days`. as_on = due + 1 gives 0 interest. A restart (part-payment) re-anchors month boundaries, so the restart property only holds for start days 1 to 28. |
| D5 | Most rules in DOMAIN 3.2 and 3.3 have no severity. Confirm depends on severity. | An "On failure" column is added to every rule. A blocking finding that is `failed` or `needs_review` blocks confirmation until it passes or is accepted with a reason. |
| D6 | Scorers and thresholds are ambiguous (X-NAME-SIMILAR, X-QTY); X-QTY contradicts itself; INV-TOTAL has a double tolerance; INV-TAX-RATE gives no status. | X-NAME-SIMILAR uses `token_set_ratio >= 80`. X-QTY pairs lines by `token_set_ratio >= 70`: equal is passed, different is failed, no match or an unknown unit is needs_review. INV-TOTAL: printed round-off must give an exact sum (within 1 paisa); with no round-off line, a difference up to ₹1.00 passes. Off-slab tax rate is needs_review (warning), with a tolerance of 1 paisa per line. |
| D7 | 11 rules have no message key; the notice cites `SEC-18-REFERENCE`, which is not a rule; params carry English words. | Add every key in en and hi. `SEC-18-REFERENCE` becomes a documented notice rule. Params whose name ends in `_key` carry i18n keys, which the web layer translates. The notice gets third-person `notice.basis.*` strings. |
| D8 | Repair, look-alike flags, acceptance and confirmation have no stored state; a recompute would erase `needs_review`. | Paper status gains `repairing`. Claims gain `repair_via`, `repair_outcome`, `review_flag`, `animate`, provider, model and `prompt_version`. A new `acceptances` table keys on rule, subject fields and claim versions. Any change clears `confirmed_at`. |
| D9 | The Provider protocol cannot carry the replay key, the strict retry or the rotation; crops are cut from the wrong image. | Add `ReadContext(original_sha256, kind, prompt_version, rotation, attempt, field, box)` to `extract` and `reread`. Crops come from the prepared image. `ProviderResult` adds `replayed` and `recorded_from`. Replay reports `provider="replay"`. |
| D10 | Replay eval runs would overwrite live results; "wrong and passed" has no denominator. | Replay writes `eval/reports/replay.json`; only a live provider writes `latest.json`. The metric is computed on first-read values: wrong fields that no applicable rule failed or flagged, over all scored fields and over wrong fields, both with n. |
| D11 | CSRF is described three ways; the size cap runs after form parsing; Host has no port; WAL keeps deleted bytes; pages are cached. | Double-submit: an HttpOnly cookie named per port, checked against the `X-CSRF-Token` header or a form field. A 15 MB cap in ASGI before parsing. The Host allow-list includes the port. After a delete, `VACUUM` plus `wal_checkpoint(TRUNCATE)`. `no-store` on all non-static responses. `camera=()`. |
| D12 | Provider precedence between environment and database is undefined, which could bypass Gemini consent. | An explicitly set `MUNIM_PROVIDER` pins the provider (Settings shows it locked). Gemini is used only when consent is stored. Language precedence: cookie, then setting, then environment. |
| D13 | Missing routes and columns: delete paper, hand entry, delete payment, notice days, addresses, PAN, derived image. | Added to API and ARCHITECTURE. PDFs are read from page 1 in v1. One paper of each kind per case. |
| D14 | Gate 3's exit uses E2E-1 and E2E-3, which need Gate 4 features. | Gate 3 uses E2E-1a and E2E-3a (no stamp, clock or evidence-file asserts). The full E2E-1 and E2E-3 move to Gate 4. |
| D15 | DESIGN uses `app/` paths; 40 px controls fail the 44 px rule; letter-spacing cannot make GSTIN groups; review boxes in highlighter are 1.45:1; the case list's primary action has no route; "जाँच में सही" means "correct". | Package paths throughout. 44 px controls. GSTIN groups as spans with margins. Review boxes use a dashed ink outline. "New case" is the primary action. Hindi "Passed" becomes "जाँच में पास" (for the native reviewer). |
| D16 | Mukta has `tnum` but no `lnum` feature. | Its figures are lining by default (no `onum`), so `check_fonts` requires `tnum` and accepts lining-by-default. No fallback font is needed. |
| D17 | htmx 2.0.11 is 0BSD, not BSD-2-Clause. | THIRD_PARTY corrected. |
| D18 | The clock strip has no states for missing inputs or an unconfirmed case. | States: missing input (named, with a link), provisional before confirmation, not yet late, interest off for medium enterprises, Bank Rate unconfirmed note. |
